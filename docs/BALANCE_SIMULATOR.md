# Регулярная проверка баланса

Из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\balance.ps1 check --n 1000 --bench-k 1000 --seed 20261106 --threads 6 --name current
```

Скрипт автоматически собирает текущий проект, запускает изолированные проверки настоящего `Game`, затем симуляцию. Если Godot установлен в другом месте, задайте `$env:GODOT = 'C:\путь\Godot.NET.exe'`. Нужен Godot с поддержкой .NET. Команда без аргументов запускает `check` с настройками по умолчанию. `-SkipCompilation` разрешён только при заведомо свежей сборке. Журналы каждого запуска находятся в `balance/out/_cli/<идентификатор>/`.

Для быстрой проверки работоспособности используйте `--n 20 --bench-k 20 --validation-n 4`; для выводов о балансе нужны сотни или тысячи прогонов. Маленькая выборка отмечается в подробном отчёте. `--n` задаёт число кампаний на каждый профиль, `--bench-k` — размер боевых стендов. Стенд боссов и пробы стратегий используют не меньше 100 прогонов на сценарий. `--validation-n` (по умолчанию 12) задаёт объём внутренних тестов воспроизводимости. Одинаковые данные и сид дают одинаковые исходы независимо от числа потоков; время выполнения может отличаться.

## Что проверяется

- Четыре стратегии: новичок, обычный игрок, опытный игрок и оптимизатор. Моделируются сбор ресурсов, развитие, навыки, экипировка, фонари, охрана, пять боссов, смерти и могилы.
- Дуэли с боссами при разных уровнях героя, эффективность оружия, вставок и каждого уровня навыка.
- Стратегии без фонарей, с большим количеством фонарей и с ранним нападением на босса.
- Бюджеты появления врагов, предел стрелков, фиксированные характеристики видов, ускоренные предупреждения боссов, дополнительные корни, ограниченный запас лечения за убийства.
- На настоящем `Game`: формулы героя, цены и открытия навыков, характеристики врагов, бюджеты столкновений, предупреждения Рощи во всех фазах, паузы Глубинного Стража, запас лечения и смысл результатов без побед.

Цели сложности берутся из `balance/targets.json`. Это проектные ориентиры, которые нужно согласовать с желаемой сложностью игры. Статистические отклонения от них — повод изучить конкретный сценарий и провести плейтест.

## Результаты

В `balance/out/current/`:

| Файл | Назначение |
|---|---|
| `CHECK.md` | краткая сводка: победы, остановки подготовки, лимиты боевых попыток, смерти, время завершённых кампаний |
| `quality.json` | статус, доверительные интервалы, замечания, ограничения модели, отпечатки исходников и сборки |
| `current.md` | подробные результаты: этапы, оружие, навыки, ресурсы, боссы и подозрительные стратегии |
| `current.runs.csv` | каждый прогон с сидом, исходом, причиной остановки (`stop_kind`) и временем этапов |
| `current.summary.json/csv` | агрегированная статистика |
| `current.model.json` | снимок чисел игры, версия схемы 3 (новая кривая здоровья; старые снимки нужно пересоздать) |

`quality.json` различает `model_error` (некорректные данные или проваленные тесты), `unverified` (нет актуальной сверки с Game), `balance_review` (есть замечания к балансу) и `ready` (проверки пройдены, значимых замечаний по выбранным целям нет). `ready` при небольшой выборке не означает, что баланс доказан.

Остановка подготовки означает, что бот не решился идти на босса после ограниченного числа циклов улучшения. Это ограничение стратегии бота; оно не доказывает, что игрок не сможет победить. Время прохождения при нуле побед отсутствует: `null` в `quality.json`, прочерк в Markdown/CSV, `"NaN"` в старом формате `summary.json`.

## Автоматическая проверка

```powershell
powershell -File tools\balance.ps1 check --n 1000 --seed 20261106 --name ci --strict
```

Коды завершения: `0` — проверка завершена, `1` — замечания баланса при `--strict`, `2` — ошибка данных/тестов или отсутствие сверки при `--strict`, `3` — остановка симуляции. По умолчанию замечания баланса сохраняются в отчёт и не прерывают команду. Для остановки долгого расчёта создайте файл `balance/STOP`.

Прямой запуск `Godot --headless --path . -- balance check ...` не выполняет отдельные стадии настоящего `Game` и получает статус `unverified`. Обёртка PowerShell передаёт свежий журнал контракта; отпечатки исходников и идентификатора загруженной сборки защищают от использования старой сверки. Параметры модели можно менять через `--overrides proposal.json` и сравнивать на одинаковом сиде. Старые снимки без версии схемы нужно пересоздать.

## Границы достоверности

Это быстрая модель одиночной игры с шагом боя 0,05 секунды. Геометрия мира и арен, кооператив, физический подбор предметов и движения игрока полностью не воспроизводятся. Дополнительные корни используют вероятность попадания `FollowupHitShare`; пространственные эффекты реликвий и hit-stop приближены. Часть таймеров врагов и боссов задана таблицами, поэтому после изменений механик нужно поддерживать таблицы и проверки соответствия.

`check` не меняет параметры игры. Кампании не обращаются к пользовательским сохранениям; тестовые стадии `Game` используют отдельные каталоги запуска. Для окончательного решения об изменениях сложности проверяйте сценарии с находками в живой игре.
