# Lanther: мультиплеер (часть 1 — сетевая основа)

## Что выбрано и почему
* Godot 4.7.2 .NET. Редактор/движок на этой машине (`Godot Engine` из Steam) **уже содержит GodotSteam** (синглтон `Steam`, класс `SteamMultiplayerPeer`) — это проверено запуском
  (`LAMP_STAGE=steamprobe`). Официальных .NET-сборок GodotSteam нет, поэтому плагин вызывается **динамически** из C# (`ClassDB`, `Engine.GetSingleton`), без
  compile-time зависимости. Steamworks.NET и GDExtension-пиры не смешиваются.
* Транспорт изолирован интерфейсом `INetTransport` (`Scripts/Net`): `EnetTransport` (локальная сеть, разработка) и `SteamTransport` (лобби + P2P/SDR через GodotSteam).
  Игровая сетевая логика (`NetService`, `NetNode`) знает только `MultiplayerPeer`.
* Host-authoritative: хост — peer 1, принимает рукопожатие, проверяет версию/число игроков/частоту запросов, рассылает состояния.
* **ENet-проверки не доказывают работу Steam P2P** (см. «Проверено / не проверено»).

## Устройство (Scripts/Net)
| Файл | Роль |
|---|---|
| `NetTypes.cs` | роли/состояния, константы (`MaxPlayers=4`, порт, `Protocol`, `GenVersion`), `NetPlayer` |
| `INetTransport.cs`, `EnetTransport.cs`, `SteamTransport.cs` | транспорты |
| `NetService.cs` | статическое состояние сеанса (переживает перезагрузку сцены): Host/Join/Leave, список игроков, события |
| `NetNode.cs` | RPC: `RpcHello/Welcome/Reject/Roster/State/Snapshot`, проверки хоста, интерполяция удалённых игроков |
| `Game.Net.cs`, `Game.NetMenu.cs` | интеграция в Game: удалённые персонажи, имена, меню «Мультиплеер», выход/потеря связи |

Рукопожатие: клиент → `RpcHello(protocol, version, genVersion, name)`; хост проверяет и отвечает `RpcWelcome(seed, genVersion, id, позиция хоста, список)` либо `RpcReject(причина)`.
Клиент генерирует мир из seed хоста (перезагрузка сцены, если seed отличается) и **не пишет сохранения** (защита локальной одиночной игры).
Идентичность: `NetPlayer.UserId` берётся у транспорта (`get_steam_id_for_peer_id`), а не из сообщений клиента.
Защита: ограничение частоты `RpcState` (40/с), отбрасывание нереальных скоростей, ограничение координат/здоровья, таймаут рукопожатия (6 с), лимит 4 игроков.

## Steam
* Нужны: запущенный Steam, GodotSteam в движке **и в экспортных шаблонах**, AppID.
* AppID игры — 5523470 (`NetConst.DevAppId`, подставляется при запуске не из Steam). Для запуска из редактора: файл `steam_appid.txt` с `5523470` (AppID игры) в корне проекта — он в `.gitignore` и в `exclude_filter` экспорта;
  **в релизной сборке должен быть собственный AppID** (файл рядом с exe не нужен, когда игра запускается из Steam).
* Лобби: `createLobby` → после `lobby_created` (вне обратного вызова!) создаётся `SteamMultiplayerPeer.create_host(0)`; `server_relay = true`.
  Известная особенность: создатель лобби тоже получает `lobby_joined` — это не вход клиента (игнорируется).
* Приглашения: `join_requested` (Overlay) и аргумент запуска `+connect_lobby <id>` → `NetService.Join("steam", id)`.

## Проверено / не проверено
Проверено автотестами (`tools/run_checks.ps1`, `-NetOnly` — только сеть):
* два процесса игры по ENet: рукопожатие, один и тот же seed, обмен позициями, отображение второго персонажа, выход клиента, отказ при несовместимой версии;
* настоящий Steam на одной машине (`netsteam`): создание лобби, `SteamMultiplayerPeer` как `MultiplayerPeer` игры, хост = peer 1, Steam ID хоста получен от Steam.

**Не проверено** (нужны два Steam-аккаунта/компьютера): вход второго клиента в Steam-лобби, P2P/Relay между двумя компьютерами, приглашение друга, вход через Overlay,
список лобби, 3–4 игрока, экспорт Windows с GodotSteam-шаблонами.
