# Герои и миры

Игра запускается как в Terraria: **герой → мир → игра**. Герои и миры хранятся отдельно и не зависят друг от друга. Старых форматов сохранений игра не поддерживает.

## Файлы

```
user://characters/<CharacterId>.json   герой (+ .bak — последняя корректная копия)
user://worlds/<WorldId>.json           мир   (+ .bak)
user://worlds/<WorldId>.png            миниатюра карты 160×32 (одна точка — блок 4×4 клетки; неисследованное темнее)
```

`CharacterId` и `WorldId` — случайные 12 знаков, не зависят от имени. Запись атомарная: временный файл → замена; прежний файл копируется в `.bak`, только если он разбирается.

| Герой (`CharacterSave`) | Мир (`WorldSave`) |
|---|---|
| имя, внешность (`Look`), время игры | название, seed, версия генератора, сложность, время игры |
| инвентарь, запас построек, вставки | изменения карты (`Obj`), постройки и их настройки, склад (`Stock`) |
| оружие, инструменты, хотбар, реликвии | древние фонари (зажжены / выполнены), места интереса, исследованная карта |
| уровни навыков, уровень, опыт, здоровье | жители, события, торговля, спил кустов, посаженные клетки |
| чертежи, фрагменты, журнал находок, подсказки | побеждённые боссы, уровень маяка, сюжетный прогресс, открытые категории улучшений |
| личное положение в каждом мире (`Worlds[WorldId]`) | |

Навык принадлежит герою: он не пропадает в другом мире. Категории улучшений открываются миром (по зажжённым фонарям биома), поэтому в новом мире навык остаётся, а новые вкладки открываются по мере исследования.

## Запуск

* Одиночная игра: меню → «Играть» → выбор героя → выбор мира → старт (`Game.StartSolo`).
* Хост: «Мультиплеер» → Steam (или локальная сеть) → герой → мир (+ тип лобби: друзья / публичное) → «Создать лобби» (`Game.StartHostSession`). Мир принадлежит хосту, он его и сохраняет.
* Гость: «Мультиплеер» → ID лобби, либо приглашение Steam (`NetService.Invite`) → **только герой** → подключение (`Game.StartGuestSession`). Игрок попадает в мир хоста, мир на стороне гостя не создаётся и не сохраняется. Сохраняется только герой (раз в 10 с, при выходе и при потере связи).
* Пауза → «В главное меню» сохраняет и возвращает к выбору. Герой и мир не удаляются, пока они в активном сеансе.

Выбранные пара герой/мир хранит `GameSession` (статическое состояние переживает перезагрузку сцены), файлы читает и пишет `SaveManager`, перенос данных в игру — `Game.Save.cs` (`ApplyWorld`, `ApplyCharacter`, `BuildWorld`, `BuildCharacter`).

## Кооператив

* Предметы гость получает только от хоста (`RpcGrant`, проверка отправителя и размера); сетевых запросов на выдачу себе предметов нет. Хост проверяет внешность гостя (индексы палитр) при рукопожатии.
* Внешность передаётся в рукопожатии и в списке участников; удалённые игроки рисуются своими слоями.
* Протокол `lanther-net-6`.
* Не реализовано в первой версии: миграция хоста, распределённые транзакции, Steam Cloud, восстановление после любых сбоев.

## Внешность

Слои `Assets/Sprites/Player/Look/*.png` (кожа, одежда 1 и 2, детали, волосы) рисуются поверх друг друга и тонируются палитрами `Look`; контур `LookArt` строит в коде по силуэту этих слоёв. Генератор: `python tools/GraphicsGenerator/make_look_art.py` (также рисует иконки и фон экранов выбора в `Assets/UI/Flow`). Новые причёски и фасоны — это новые строки в `HAIR` / `VARIANTS` скрипта и числа в `Look` (`HairN`, `VariantN`, названия).

## Проверки

`powershell -File tools/run_checks.ps1` (отдельно: `-NetOnly`, `-NetOnly -NetCase flow`).
Стадии: `sessions` (один герой в разных мирах, разные герои в одном мире, независимость, удаление), `flow` (скриншоты всех экранов; `LAMP_STAGE=flow` с `--resolution 1280x720` и `1920x1080`), `menu` (резервная копия мира), `netflowhost` / `netflowjoin` (настоящий путь хоста и гостя через ENet), `savesmoke` (тестовые сохранения `testsaves/*/{characters,worlds}`). Steam-транспорт автоматически проверяется стадией `netsteam` только при наличии GodotSteam и запущенного Steam.
