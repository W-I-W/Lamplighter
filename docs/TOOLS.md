# Инструменты проверки проекта

| Команда | Время | Что делает |
|---|---|---|
| `python tools/lint.py [--strict] [--only json,res,loc,...]` | ~1 с | статический линтер без Godot: JSON и `targets.json`, ссылки `res://`, `.uid`, переводы строк и маркеры слияния, покрытие `lang/en.json` (с учётом шаблонов и префиксов `Loc.T`), плейсхолдеры, стадии `LAMP_STAGE` и `run_checks.ps1`, ссылки в `docs/`, мусор в корне, `tuning.tres` |
| `powershell -File tools\check.ps1 lint` | ~1 с | то же через единый вход |
| `... check.ps1 quick` | ~5 мин | lint + `dotnet build` + сверка баланс-модели с настоящим `Game` |
| `... check.ps1 balance [-N 200 -Seed 20261106]` | десятки минут | quick + симуляция `balance.ps1 check` + шлюз против эталона |
| `... check.ps1 full` | очень долго | quick + все стадии `tools\run_checks.ps1` |
| `... check.ps1 baseline` | мгновенно | сохранить последний прогон баланса как `balance/baseline.json` (коммитится) |
| `python tools/balance_gate.py diff [--run DIR]` | мгновенно | сравнить прогон с эталоном: победы (доверительные интервалы), время прохождения, новые замечания |
| `python tools/balance_gate.py list` | мгновенно | прогоны в `balance/out/` |

Код возврата 0 — всё хорошо, 1 — ошибки/регрессии. Шлюз сравнивает только сопоставимые прогоны (один seed и `--n`); иначе пишет предупреждение. Подробнее о симуляторе: [BALANCE_SIMULATOR.md](BALANCE_SIMULATOR.md).

## Ручная проверка (живой плейтест)

| Команда | Что делает |
|---|---|
| `python tools/playtest.py checklist [--out playtest_checklist.md]` | чек-лист ручной проверки проекта и боссов, экономики, темпа, техники + опросник игрока |
| `python tools/playtest.py report [LOG ...] [--profile average] [--md out.md]` | читает телеметрию `diagnostics_log.jsonl` (настройки → «Диагностика» или `LAMP_DIAG=1`), печатает контрольные точки 15 мин / 1 ч / 3 ч / 5 ч / 10 ч и сверяет с критериями [PLAYTEST.md](../PLAYTEST.md) и `balance/targets.json` (смертей в час, время первого босса): ✅ / ⚠️ ПРОВЕРИТЬ. Код 1 — есть пункты к проверке, 2 — нет данных |

Порядок: сыграть сессию с включённой диагностикой → `report` → заполнить `checklist` вместе с игроком → правки вносить только там, где метрики и ощущения совпали → `tools\balance.ps1 check` и `tools\check.ps1 balance`.

## Отладка прямо в игре (F10)

Окно открывается клавишей **F10** в отладочной сборке, при включённой «Диагностике» в настройках или с `LAMP_DEBUG=1`. У гостя сетевой игры недоступно. Пока курсор в поле ввода, клавиши не доходят до игры (**Esc** или клик по миру возвращает управление); клики над панелью мир не получает. Кнопка ⇄ переносит панель на другую сторону.

| Вкладка | Возможности |
|---|---|
| Состояние | FPS, уровень, здоровье, урон, маяк, боссы, фонари, регион, враги с стоимостью и **бюджетом столкновения**, память; снимок состояния в буфер обмена (JSON) |
| Развитие | пресеты этапов «Середина / Поздняя / После финала» (только повышают, без дублей, перед прыжком копия сохранения `*.debugbak`); уровень героя, инструмент, маяк, боссы, фонари по регионам, все навыки, ресурсы, телепорт к маяку, стражам и регионам |
| Баланс | все числа `CombatTuning` (≈60) с фильтром; правка действует сразу; изменённые подсвечены, ↺ сбрасывает; «Копировать изменения» (строки для `tuning.tres`), «Сохранить в tuning.tres» (из проекта, с копией в `user://tuning_backups`); переключатель сложности мира |
| Утилиты | бессмертие, скорость игры (пауза … ×4), лечение, убить врагов, создать врагов любого вида |

Правки чисел влияют на новых врагов и расчёты на лету. Проверка: `LAMP_STAGE=debug` (в `run_checks.ps1`). После подбора чисел прогоните `tools\check.ps1 balance`.
